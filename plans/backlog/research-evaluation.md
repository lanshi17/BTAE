# BTAE 研究评测计划（草案）

状态：`planned` · 设计状态：`draft`

本文定义如何验证 BTAE 的方法假设，不把产品检查通过当作收益证明。所有结果需要记录数据来源、环境、模型/工具版本、提示、任务、预算、执行顺序、失败与不确定性；没有独立标注或对照结果时，指标保持 `unknown`。

## 1. 研究问题

1. 实体设计、契约和证据是否减少长期演进中的设计漂移与回归缺陷？
2. 双向影响分析对独立标注的变更影响集合有何精确率、召回率和截断率？
3. 分级上下文是否在保持 C0 约束完整的同时改变上下文体积、检索时间或 Token 成本？
4. 治理、审批和重跑成本是否抵消潜在收益？

“优于 SDD”不是默认假设；只有预注册对照和重复实验支持时才能提出比较结论。

## 2. 条件与对照

| 条件 | 过程约束 |
| --- | --- |
| A | 自由 Agent 编码，保留同一任务、模型、工具和预算 |
| B | 规格、计划与任务驱动，但不使用实体双向追溯 |
| C | 规格驱动加实体映射与追溯，不启用完整治理门禁 |
| D | 完整 BTAE：实体、契约、影响、上下文和 Evidence 门禁 |

初始开发、需求变更、故障修复和多轮演进分别作为场景；多 Agent 协作是独立因素，不能与方法条件混杂。每个场景至少保留任务输入、初始仓库、变更集、执行日志、最终代码和评审标签。

## 3. 影响与上下文评测

### 3.1 独立影响标注

标注者从代码、设计、测试和证据变更前后快照建立真实影响集合，先于运行 EPE 生成结果。每条标注包含实体 ID、影响类型（确定/候选）、依据路径、标注者和复核状态。工具自身的图或传播结果不能充当真值。

报告至少包括：

- precision、recall、F1，按实体类型和变更类型分层；
- `candidate` 与 `determined` 的分别统计；
- 预算耗尽、静态盲区、删除/移动实体的截断率；
- 构图时间、重解析文件数、全量/增量字节量和失败恢复次数。

当前 [`tests/benchmarks/impact_labeled/cases.json`](../../tests/benchmarks/impact_labeled/cases.json) 只包含三个合成回归场景；它可证明实现稳定性，不能作为真实项目的独立召回率基准。

评测脚本 [`tests/benchmarks/impact_labeled/evaluate.py`](../../tests/benchmarks/impact_labeled/evaluate.py) 可对同一 JSON 结构输出整体及 `determined` / `candidate` 分层的 precision、recall、F1、精确匹配率和不完整标记。当前输出类型固定为 `synthetic_regression`，在独立真实标注集建立前不得把结果解释为方法效果证据。

上下文选择评测脚本 [`tests/benchmarks/context_labeled/evaluate.py`](../../tests/benchmarks/context_labeled/evaluate.py) 对 `ContextBundle` 的来源路径计算相关性 precision/recall/F1、C0 必需来源保留率、遗漏/截断、分级数量和内容字节量。CLI 同时记录选中条目数、内容字节量、本地耗时和 Token 估算器状态；当前没有可靠估算器时 `estimated_tokens` 保持 `null`。其合成样例同样只用于接口回归；真实相关性、成本和盲评仍需独立数据。

### 3.2 上下文质量与成本

为每个任务记录 C0–C3 选择、遗漏、来源类型、预算、字节数、估算 Token、解析时间和缓存命中率。独立评审者对“完成任务所需的最小充分上下文”进行盲评，记录相关性、约束遗漏和错误混入；另记录人工维护设计、审批、索引和重跑的时间成本。

没有可靠 Token 计量或价格依据时只报告字节、条目数和本地耗时，不虚构金额或节省比例。外部向量/BM25 后端必须单独记录版本、索引构建成本和降级路径。

## 4. 运行与报告门槛

实验配置、原始结果、聚合脚本、失败运行和排除理由均需版本化；报告区分探索性结果与预注册确认。重复运行至少保留随机种子或确定性输入摘要，使用置信区间或不确定性说明，不以单次通过测试推断方法收益。

在独立标注集、对照条件和成本记录存在前，WP-12/WP-13 只能标记“本地能力已实现、研究证据待补”，不能关闭外部发布限制。
