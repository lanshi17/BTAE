# TASK-module-dependency-aggregation：模块归属与依赖聚合

- 分类：Feature；风险：中；影响 MOD-003 Graph、MOD-006 Verification；写入范围为图构建、模块/架构设计和测试，保留其他现有工作。
- 依据：MOD-003 §4 和 MOD-006 §4 要求明确模块归属、聚合实际依赖与模块循环。当前只存在 Source 级导入边，多个文件跨模块循环可能完全不形成文件级循环。
- 设计：`engineering/epe.yaml` 可选 `managed.module_roots`，为 Module ID 到仓库相对目录数组的映射。开启时每个解析的 Python 文件恰好属于一个根；重叠归属、未知或非 Module ID、非法路径均报错并拒绝发布，未归属文件输出静态分析盲区。根据已解析内部 Source 依赖，跨模块产生 `depends_on`，包含源文件、行号、源和目标路径的静态来源；模块内部引用不生成自环。未知/外部导入不伪装为内部依赖。模块根和构图版本参与快照兼容校验，当前旧图必须重建。未配置时保持旧行为，不宣称已检查模块级循环。
- 验收：构造无文件级循环但存在模块级循环的真实样例，验证聚合来源和架构阻断；覆盖无歧义、重叠、未归属、失效配置、同模块、增量与全量一致及快照新鲜度。设计 draft。

- 结果：显式归属、聚合、盲区、版本失效与架构循环证据已接入；真实 CLI 验证了文件级无环但模块级有环的场景。定向 16 项、全量 162 项通过；记录见 `reports/evaluations/module-dependency-aggregation.json`。未配置归属时模块覆盖为 unconfigured，不能证明模块级无环。
