# 审批签名与撤销

- 类型：Bugfix / Feature；风险：high；涉及 SPEC-001、MOD-005、MOD-007、MOD-009。用户授权实现并不构成审批。
- 问题：调用者可在记录中填写名单身份；字符串匹配无法证明身份。现有完成门禁也忽略风险范围与撤销。
- 范围：设计审批、SSH 公钥签名适配器、CLI 审批导入与完成门禁、机器 Schema、测试和相应文档；不改变其他工作树内容。
- 契约：配置 `approval_trust.identities.<id>` 的 SSH 公钥、身份类型及允许风险，维护者须独立保护配置。记录签名覆盖除 `signature` 外的全部字段；使用 `ssh-keygen -Y` 和 `epe-approval` namespace 验签。审批记录必须含 ID、实体、revision、决策、身份、授权来源、UTC 时间、风险范围和签名。导入追加不可覆盖，调用者提供的身份名或 role 不是凭据。
- 撤销：可信签名的 `revoked` 记录通过 `supersedes` 显式引用同实体、同 revision 的既有批准；不使用时间顺序裁定。完成检查重新验签并排除已撤销记录；缺少可信配置、失效签名、引用冲突一律不能作为授权。
- 验收：真实 SSH 密钥正例、冒名及字段篡改反例、风险不匹配、撤销、设计变化与重复 ID；不支持 SSH 或缺配置时阻断。
- 信任边界：仓库配置和审批记录本身不能证明外部人类授权，只有受保护的公钥配置及私钥持有者提供该证明；本地 CLI 不提供宿主隔离。独立评审和身份类型依赖受保护配置。
